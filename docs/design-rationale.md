# 復盤如何轉為 Agent 行為

設計輸入為使用者提供的 2026-10-16 專案溝通復盤，以及 2026-10-16 AI TEAM 教練 1on1（含 2026-10-19 整理的社群交流摘要）；亦沿用既有 project-kickoff-planner 的證據、範圍、變更與卡關規則。這些是個案經驗，未作為普遍有效性的實證。原始紀錄、個人帳號、對話截圖與專案商業數字不納入倉庫。

| 復盤觀察 | 內化行為 | 避免誤用 |
| --- | --- | --- |
| 身兼二職導致判斷拉扯 | 每次說明本職、PM 與其他專業各自輸入 | 不要求使用者放棄本職品質 |
| 先拋解法，痛點沒被理解 | 先描述阻礙、缺口與影響 | 不把增聘或系統化當預設答案 |
| 技術困難被單向丟回使用者 | 請工程回傳限制、可行選項與代價 | 不捏造技術方案，不替工程估時 |
| 請協助變成人情負擔 | 寫成有範圍的專案交接 | 不宣稱可直接調動別人的時間 |
| 思考擴散 | 當下阻礙與後續議題分開 | 必須改制度才解得開時仍呈現根因 |
| KPI 缺基準與定義 | 檢查量測來源、歸因與合理性 | 不沿用個案目標數字 |
| 長工期需要原因與取捨 | 先取得瓶頸證據再比較範圍 | 不把個案會員排除條件變預設政策 |
| 一人拍板，AI 執行 | 找授權決策角色並區分建議與採納 | 不擅自指定誰有決策權 |
| PM 的產出是下個人的輸入 | 按接收者約定最小交付 | 不硬性新增文件套件或管理介面 |

相對舊版，保留名稱以便更新，移除 HTML 預設交付。依使用者後續要求，供人決策的輸出必須使用 `i-have-adhd`，並於 README 說明 Codex 與 Claude Code 的依賴安裝與啟用方式；不把簡短易讀視為實際載入 Skill 的替代。
