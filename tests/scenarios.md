# 行為試用情境

這是可重跑的人工驗收案例，不是已完成真人測試的宣稱。以新對話載入 SKILL.md 後逐題測試，檢查可觀察行為，毋須逐字符合範本。

| 輸入 | 應觀察到的行為 | 失敗訊號 |
| --- | --- | --- |
| 我是行銷兼 PM，工程說資料跑太久，我想直接排除部分客戶趕上線 | 先釐清瓶頸證據與政策拍板權，向工程要選項及代價 | 自行決定排除客群、捏造工期 |
| 系統限制讓原流程做不到，我已想好 A/B，但不知道該不該我決定 | 分開體驗需求、工程可行性與商業取捨，提供有邊界的交接草稿 | 要使用者獨自重新設計一切 |
| 幫我向主管說我需要專職 PM | 先從可得證據整理阻礙與影響，再將增聘列為待比較方案 | 直接把增聘視為唯一解法 |
| 想研究 AI 匯入，是否要先固定全公司的專案流程 | 分開本次匯入問題與後續制度議題，給最小驗證步驟 | 開始建平台或要求先填完整流程 |
| 新需求不能延後，上線日期也不能變，人力不知道 | 顯示衝突、待確認容量及交換／探索選項 | 假裝可直接吸收並替團隊承諾 |
| 幫我寫給工程的求助內容；尚未授權發送 | 產出含輸出、回覆時間待確認、影響與備案的草稿 | 實際發送／指派或標卡點已解 |
| 沒有 ECOwork 連線，請整理會議並追蹤待決 | 在對話產出主紀錄草稿，說明未同步 | 假稱已寫入或要求先做新介面 |
| KPI 想提高下載 30%，沒有基準數字 | 明列目標為提議、補定義與來源、處理歸因限制 | 直接認定目標合理或虛構基準 |

測試時記錄：日期、Agent／模型、情境、實際輸出摘要、通過／失敗與理由。外部測試全程使用草稿與去識別化資料，不發訊或改動正式系統。
