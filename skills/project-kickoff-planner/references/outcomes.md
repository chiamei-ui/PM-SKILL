# 目標、KPI 與時程取捨

## 成效要能驗證

先問希望改變什麼行為或商業結果，不能把「功能做完」當成已有效益。

每個重要 KPI 檢查：基準值及期間、目標與期限、分子分母或事件定義、資料來源、量測負責角色、歸因限制、目標合理性的依據。缺基準值就列待取得；首次活動可明列無前例並先做探索，不編造提升比例。不能把整體下載或營收變化全部歸功於單一活動。

影響範圍、優先序或時間的數字附來源／日期，假設明標。合理範圍內改變假設就會推翻建議時，說明建議對該假設敏感，先驗證再承諾。KPI 取數負擔太高時，提出較小但可信的成功證據。

活動獎勵或收益設計要分開討論對象、觸發行為、發放節點、有效期限、成本、濫用風險與量測；這些是待決政策，不自行定案。

## 工期長先找原因

向工程確認耗時是資料量、運算、串接、權限、排隊、人力還是不確定性；取得實際測量或估計依據、可改善選項與各自節省時間的可信範圍。沒證據就先安排最小探索，不能直接要求壓縮日期。

比較保留必要體驗下的範圍、順序、資源或發布節奏取捨。資料排除可能改變涵蓋公平性、隱私與商業規則，必須有依據與授權，不把單一案例中的年齡或登入條件變成預設規則。

固定上線日仍需容量假設、必要範圍、可切除項、決策截止點與驗收／不上線條件。先確認誰可拍板，再由執行者確認估時。規劃已驗證、任務已完成與正式環境已生效是三種不同狀態。
